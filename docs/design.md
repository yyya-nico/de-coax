# 設計と出典

## 出典

coaxの手元ソース（コミット `2d9f2c263a3b080ecef3a8ede1eb86c6afa48405`）から、MB86H47A、DiB8096、FR30アセンブラー・シミュレーター、I2C、ISO7816、USBアクセスの各パッケージを取り込みました。元プロジェクトは [Till0196/coax](https://github.com/Till0196/coax) です。元の著作権表示・SPDX識別子を保持しています。モジュール名と内部importを `cech.local/driver` へ変更しています。

px4_drvの手元ソース（コミット `560d296c7e99f2e9e438630dec415a1bb09a064d`）から、`winusb/src/WinSCard_PX4` のWinSCard API互換処理、エクスポート定義、共通カードコマンド定義と、BonDriverのインターフェース定義を取り込みました。手元の参照ツリーに含まれる変更の有無は確定できていないため、このコミットの完全な再現コピーという扱いではありません。取り込んだファイル自体が本成果物の対応ソースです。

元のcoaxとpx4_drvのフォルダーは変更していません。px4_drvの機種固有レジスター設定は、MB86H47A/DiB8096と異なるため転用していません。

## 層の関係

```text
TVTest / EDCB
  | BonDriver API                  | WinSCard API
  v                                v
BonDriver_CECH.dll <---------- WinSCard.dll
  | 同じプロセスのUSB所有者        | 外付けはWindowsへ転送
  | 継承ハンドルだけのローカルパイプ
  v
cech-host.exe
  | 制御・カード処理              | 独立したTS受信処理
  v                                v
receiver / DiB8096 / MB86H47A / ISO7816
  |
pkg/usbio のWinUSB実装
```

DLLは共有バックエンドを参照管理します。チューナーとカード接続の最後の所有者が閉じると、ホストも終了します。カード接続を残してチューナーを閉じる場合は、TSだけを停止します。ホストの起動はウィンドウを表示せず、子プロセスへ継承するハンドルもstdin/stdout/stderrの3つに限定しています。

制御要求とカード要求はDLL側の制御ロックで直列化します。TSの受信スレッドとアプリへ渡すキューのロックは分離しています。ホスト側もカード応答待ち中にTSを読み出せる構成です。DLLのキュー上限は32MiBで、上限超過を隠したまま受信成功を返すことを避け、エラー状態へ移します。この上限と制御タイムアウトは現時点の試験用設定であり、運用負荷下での最終調整値ではありません。

ホスト間のネットワーク公開、システムサービス登録、USBドライバーの再インストールは不要です。代わりに、この方式のカード共有は同じアプリプロセス内に限られます。

## coax由来の経路に加えた変更

- 周波数ごとのTMCCキャッシュ。TMCC同期・TV用階層のMPEGロック・手動選局に必要な全パラメーターを確認した値のみを保持します。失敗時はそのエントリーを削除し、自動探索へ戻ります。USBエラーの操作を自動再送することは避けています。
- フルセグ階層のロック判定をBonDriverの選局成功条件へ追加しました。
- 最長インターリーブの待機計算で、選択された階層ではなく常に階層Aを参照していた箇所を修正しました。階層AとBの深さが異なるケースを単体試験で検査しています。これが手元の「つかみの悪さ」の原因だったという実機での立証には至っていません。
- チューナー校正から再探索までを含む選局に、1回の絶対期限を設けました。単一のUSB要求はその転送タイムアウトまで戻らない場合があります。
- USB制御・コマンド送信の短い書き込みをエラーにし、TSデータと同時に返されたUSBエラーも呼び出し元へ維持しています。
- TSフレーマーは同期候補を次の192バイト位置でも確認してから受理し、初期の端数と受信中の同期喪失を計数します。
- TS解析ではadaptation field、連続性、TEI、重複、discontinuity indicator、PATのCRCとTSIDを検査します。切替ごとに解析状態を新しくします。
- Windowsのinjected USBテストで一時ファイルのハンドルが残る問題には、テスト用ファイルの後処理を追加しました。

## WinSCardの変更境界

px4_drv由来のAPI互換層は、ANSI/Unicode、メモリー割当、コンテキスト、カードハンドル、Windows側への転送処理を維持しています。`card_client.cpp` の接続先は、PX4の名前付きパイプから、このDLLの `CECHCardOpen/Call/Close` へ変更しました。カード状態・APDU・ATRはさらにローカルパイプでGoホストへ渡します。T=1はcoax由来の `pkg/iso7816` が担当します。

デバイスが再オープンされた場合はハードウェア世代を更新し、古いカード接続とトランザクションを再利用しない処理を加えています。複数のUSB機器の識別、別プロセス間の共有、抜き差し中のアプリの回復挙動は引き続き検証が必要です。
